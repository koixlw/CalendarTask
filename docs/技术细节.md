# 技术细节

给想改代码的人看的。日常使用看 [使用手册](使用手册.md) 就够了。

## 技术栈

**Python 3.10+ · PySide6 · SQLite（FTS5）**

没有前端、没有服务端、没有数据库服务器 —— 就是一个能双击运行的桌面程序。
所有数据在一个 SQLite 文件里（`%APPDATA%/PyCal/db/pycal.db`）。

## 搜索

双层架构，1:1 复刻 DesktopCal：

| 层 | 干什么 |
|---|---|
| 原生层 | SQLite FTS5 (`calendar_items_fts`) —— 取候选集，快 |
| 过滤层 | Python 富匹配 —— 颜色 / 完成度 / 类型 / 关键字 / 时间，四维 AND |

原生层表达不了的语义（比如「同一行同时含未完成 + 关键字 + 红色字」）由过滤层负责。
细节拆解见 [SEARCH_ANALYSIS.md](../SEARCH_ANALYSIS.md)。

一个容易踩的坑：**色值里的数字不能当关键字命中**。
搜 `24` 不应该命中 `#F12424` 里那个 `24` —— 所以关键字必须落在
`MarkdownParse` 之后的**可见正文**里。实现在 `primitives.ColorMatcher`。

## 打包

```bash
pip install pyinstaller
python build.py                # onedir → dist/PyCal/PyCal.exe
python build.py --onefile      # 单文件 → dist/PyCal.exe
python build.py --clean        # 先清 build/ dist/
python build.py --icon-only    # 只生成图标
```

| 项 | 说明 |
|---|---|
| 模式 | onedir (启动 ~0.3s) / `--onefile` 单文件 (启动 ~2s) |
| 图标 | `pycal/assets/pycal.ico` — 7 尺寸 (16→256) PNG-compressed 32bpp |
| 自启动 | HKCU `Run` 键（不需要管理员权限，不触发 UAC）|
| 卸载 | `python -m pycal install uninstall` 移除自启+快捷方式；加 `--purge` 连数据目录 |
| 体积优化 | `pycal.spec` 里 EXCLUDES 排掉 QtWebEngine/QtQuick/科学计算等 |

打包体积的大头是 PySide6。`pycal.spec` 的 `EXCLUDES` 排掉用不上的 Qt 模块，
能省掉一大半。

## 测试

两套并存：

| 风格 | 文件 | 跑法 |
|---|---|---|
| pytest | `test_smoke` / `test_sync` / `test_report` / `test_ai_polish` | `pytest tests/ -q` |
| 脚本 | 其余 9 个 | `python tests/test_xxx.py` |

脚本风格那套断言最多（真发鼠标事件、回车写回、八向缩放…），但 pytest 收集不到。
`tests/test_script_suite.py` 用子进程把它们拉起来，所以 `pytest tests/` 一条命令
就全跑了。

```bash
QT_QPA_PLATFORM=offscreen python -m pytest tests/ -q
```

> **离屏截图不能用来判断文字效果** —— offscreen 平台插件不加载系统字体，
> 中文全渲染成方块。要看真效果得用真平台（`tools/make_screenshots.py`
> 里 `REAL_PLATFORM=1`）。
> 想在离屏下截出带文字的图，得先 `QFontDatabase.addApplicationFont()`
> 手动灌字体。

## 版本号

**唯一来源是 `pycal/__init__.py` 里的 `__version__`。**
`pyproject.toml` 用 `dynamic = ["version"]` 从那儿读，
打包脚本和 GitHub Actions 都会核对它跟 git 标签对不对得上。

改版本就改那一处：

```python
# pycal/__init__.py
__version__ = "1.0.0"
```

## 凭据存哪

- Anthropic API key：`pycal/report/ai_polish.py`
- CalDAV 密码：`pycal/sync/accounts.py`

都是 base64 + XOR（固定密钥），存在本地 SQLite 的 `settings` 表里。
**这是混淆不是加密** —— 防「随手打开 DB 看明文」，不防拿到文件的人。
生产环境应该换 Windows Credential Manager。

## 已知限制

1. **`pycal.mcp` 没注册到系统的 MCP client**，需要在 Claude Desktop / IDE 里手动配置
2. **CalDAV OAuth 未实现**，三家都走应用专用密码
3. **壁纸原图**：当 Windows 没设置壁纸时，`make_and_set_wallpaper()` 会落回纯日历面板
4. **仅 Windows 完整测试过**，macOS / Linux 未验证
